# Поиск ошибок и оптимизация (модуль 5)

В репозитории два проекта. В `broken-app` исправлены ошибки и ускорены медленные функции.
`reference-app` взят как эталон и не менялся, его исходное состояние в коммите `94575ce`.

Логи и замеры лежат в `broken-app/artifacts`, по папкам этапов.

## Окружение

Ubuntu 26.04 aarch64 в виртуальной машине Lima на Mac с Apple Silicon. Rust 1.99.0,
nightly 1.101 для Miri и санитайзеров, gdb 17.1, Valgrind 3.26, perf 7.0,
cargo-flamegraph 0.6.14, criterion 0.8.2.

Для perf и подключения отладчика к процессу в VM выставлены `kernel.perf_event_paranoid=-1`,
`kernel.kptr_restrict=0`, `kernel.yama.ptrace_scope=0`.

## Запуск

```bash
cd broken-app
cargo test
scripts/check_all.sh <папка для логов>   # тесты, Miri, Valgrind, ASan, TSan
cargo flamegraph --bin workload
cargo bench --bench criterion
```

## Ошибки

| Функция            | Ошибка                                                               | Как найдена                                                                                       | Исправление                                  |
|--------------------|----------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|----------------------------------------------|
| `sum_even`         | цикл `0..=len` с `get_unchecked` читает элемент за концом среза (UB) | проверка std в debug, Miri, ASan; в release функция компилируется в бесконечный цикл, видно в gdb | итератор вместо индексов                     |
| `leak_buffer`      | `Box::into_raw` без освобождения, утечка                             | Miri, Valgrind, LeakSanitizer                                                                     | копия входа не нужна, считаем прямо по срезу |
| `normalize`        | удаляет только пробел, табуляции и переводы строк остаются           | тест, gdb                                                                                         | фильтр по `char::is_whitespace`              |
| `average_positive` | делит сумму всех чисел на длину всего среза                          | тест, gdb                                                                                         | считаются только положительные               |
| `use_after_free`   | чтение после освобождения (UB)                                       | Miri, Valgrind, ASan                                                                              | чтение до освобождения, `unsafe` убран       |
| `race_increment`   | `static mut` из нескольких потоков без синхронизации (гонка, UB)     | Miri, TSan, тест терял треть инкрементов                                                          | `AtomicU64`                                  |

На каждую ошибку есть регрессионный тест в `tests/integration.rs`, а `matches_reference_app`
сравнивает результаты всех функций с эталоном. Для `use_after_free` и гонки в исходном проекте
тестов не было, поэтому инструменты их не видели. Тесты на них добавлены перед проверкой.

Логи по этапам: `01_baseline` исходное состояние, `02_before_fix` отчёты инструментов до исправлений,
`03_after_fix` и `06_after_opt` чистые прогоны после исправлений и после оптимизаций.

Valgrind запускается через runner cargo, потому что `valgrind cargo test` проверяет сам cargo.
Файл `scripts/rust-std.supp` подавляет одну запись possibly lost на 48 байт: это дескриптор
главного потока внутри std. Предупреждение про `std::sync::Arc` приходит из reference-app.

## Профиль

Сценарий `src/bin/workload.rs` гоняет все функции на больших входах. До оптимизаций 58% времени
занимала `slow_dedup`, почти всё внутри сортировки, которая запускалась после каждой вставки.
Ещё 27% уходило на `average_positive`, в основном на сборку промежуточного вектора, и 6% на
рекурсивный `slow_fib`. `sum_even` и `leak_buffer` вместе давали около 6%, их я не трогал.

Flamegraph и отчёт perf до и после: `artifacts/04_profile`.

## Оптимизации

`slow_dedup`: вместо поиска и сортировки на каждом шаге одна сортировка и `dedup`.
Было O (n²·log n), стало O (n log n).

`slow_fib`: цикл вместо рекурсии, O (n) вместо O (φⁿ).

`average_positive`: один проход через `fold` без промежуточного вектора и без аллокаций.

Имена функций оставлены прежними, чтобы не ломать API и сравнение бенчмарков.
